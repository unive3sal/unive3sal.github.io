a little about me02

I’m Yuhao Deng (unive3sal). I work on AI engineering and architecture, and have worked at Ericsson, Alibaba Cloud, and Super Intelligence Inc. I started out implementing and optimizing algorithms at Ericsson. That got me interested in AI inference and parallel computing, and then in how to design the systems around them.

At Super Intelligence Inc., I designed the architecture for megahit, from cloud deployment to backend service boundaries. Its worker runs long-horizon agent tasks, with durable execution and recovery from interruptions. I also worked with researchers to put their memory research into the product. These days, I’m interested in AI agents, memory, and how they change application architecture.

When choosing an architecture, I start with what the company needs most and the metric it cares about. That guides the trade-offs between performance, delivery speed, and reliability. I also consider how much harder a design might make it for engineers and domain experts to work together.

I mostly write Rust, Python, and C++. I also contribute to cc-switch-cli, an open-source tool for AI coding assistants, where I’ve worked on the daemon, protocol compatibility, and CI. I’m looking for my next role, and I’d be glad to hear from people looking for collaborators or co-maintainers for open-source projects.

selected work05
01

megahit/

AI growth platform · Agent architecture & evaluationJul–Nov 2026 · AI Engineer / Architect · Super Intelligence Inc.
architecture+

Megahit is an AI growth platform for research, campaign planning, and execution. I designed the backend architecture and migrated its agent runtime to PydanticAI, including support for long-running tasks, shared memory, and automated evaluation.

01 · Task execution & memory

For a recurring X campaign, the agent prepares a weekly batch of posts, waits for edits and approval, then publishes at the scheduled times.

I moved task execution out of the browser connection so work could continue after a disconnect. Checkpoints and worker leases support recovery after restarts, and a saved activity feed lets users catch up when they return. Publishing uses content-specific approvals and an operation ledger to prevent duplicate posts.

I worked with the memory researcher to connect the shared memory service to the agent runtime. Chat and campaign workflows can reuse relevant context, with source tracking and separate execution state and permissions. Proposed memory updates go through the memory service.

02 · Agent evaluation

I built a routing regression suite and added multi-turn cases based on bugs we encountered: form submissions, memory corrections, draft revisions, and concurrent requests. Integration checks run in CI, while live-model evaluations track changes in agent behavior. Each run records its configuration and coverage so incomplete runs are easy to identify.

773 queries in one full evaluation run · 25 Sep 2026

The run completed without evaluation errors and recorded the build and model used.

The tests also caught a scheduling bug: approvals could expire before the last post in the following week. I adjusted the expiry calculation to cover the full posting schedule.

↳Migrated to PydanticAI in stages and removed the old agent loop.
